## 0. 為什麼標為「無效」而不是「不通過」

執行結果表面上是徹底失敗:

| | 零技巧對照組 | 波動度目標化 |
|---|---|---|
| 年化報酬 | 8.92% | **−0.85%** |
| 最大回撤 | 51.78% | **40.00%** |
| Sharpe | 0.3405 | **−0.0839** |

**但兩個數字暴露了這不是策略的失敗,是我方實作的失敗:**

1. **對照組的 MDD 是 51.78%,不是它應該是的 30%** —— 對照組的定義本身就算錯了
2. **策略的 MDD 恰好等於 40.00%**,一個治理常數 —— 那是機制卡死的指紋,不是市場的結果

**一個從壞掉的檢定得出的否證,不是否證。** 本文件記錄兩個錯誤,不主張策略二有效。

## 1. 錯誤一:回撤在對數空間才線性,我用了百分比空間

[`CP-004`](./proposals/CP-004-revised-targets.md) 與 [`strategy-2-hypothesis.md`](./strategy-2-hypothesis.md) 都用了這個推導:

```
零技巧曝險 w₀ = MDD上限 / 基準MDD = 30.00% / 88.32% = 0.3397     ← 錯
```

**這假設回撤與曝險成正比,而它不成立。** 曝險 `w` 縮放的是**對數報酬**,所以:

```
D_log(w) = w × D_log(基準),  其中 D_log = −ln(1 − MDD)

基準:D_log = −ln(1 − 0.8832) = 2.1474
正確:w₀ = −ln(1 − 0.30) / 2.1474 = 0.1661        ← 對
```

實測驗證:

| 曝險 `w` | 實際 MDD | 保留報酬 |
|---|---|---|
| **0.3397**(我用的) | **51.78%** | 31.2% |
| **0.1661**(正確) | **30.00%** | **14.9%** |

### 1.1 連帶影響一:`σ_target` 錯了一倍

```
錯誤:σ_target = 0.3397 × 73.8% = 25.1%  →  取 25%
正確:σ_target = 0.1661 × 73.8% = 12.3%
```

**策略的曝險因此系統性地高了約一倍**,這是它早期就吃到大回撤、進而觸發斜坡的直接原因。

### 1.2 連帶影響二:CP-004 第一層的門檻**內部不一致**

CP-004 第一層要求「MDD ≤ 30% **且** 保留報酬 ≥ 34.0%」。

**但沒有任何固定曝險能同時滿足這兩者:**

- 要 MDD = 30%,曝險必須是 0.1661 → 保留報酬只有 **14.9%**
- 要保留報酬 ≈ 34%,曝險必須約 0.37 → MDD 會到 **55%**

**這與我在 [`target-reassessment.md`](./proposals/target-reassessment.md) 第 1.1 節指出的、原始 `scope.md` 目標的錯誤是同一類:三個數字不能同時成立,而沒有人算過。**

**我在指出那個錯誤之後,自己又犯了一次同樣的錯。** 記錄在此。

**正確的第一層門檻應為:MDD ≤ 30% 且 保留報酬 > 14.9%。**

⚠️ **這個修正讓門檻變低,方向對我方有利 —— 必須明確標示。** 它之所以正當,是因為 `(30%, 34%)` 這一組**在數學上不可能同時達成**,而不是因為 34% 太難。任何人都可以獨立驗算:固定曝險 0.3397 的 MDD 就是 51.78%。

## 2. 錯誤二:回撤斜坡是一個吸收態

[`CP-005`](./proposals/CP-005-risk-policy-for-always-in-market.md) 3.4 節的機制:

```
factor(DD) = clip( (40% − DD) / (40% − 30%), 0, 1 )
```

**當回撤達到 40%,`factor = 0`,曝險歸零。而曝險歸零之後:**

```
曝險 0  →  權益凍結  →  回撤永遠停在 40%  →  factor 永遠是 0  →  曝險永遠是 0
```

**進去就出不來。** 實測:

| | |
|---|---|
| 首次觸及 DD ≥ 39.9% | 第 **826** 天 |
| 其後 2,444 天(全期 **75%**)的平均曝險 | **0.0029** |
| 其後回撤區間 | 39.17% – 40.00%,再未離開 |

**策略在第 826 天就實質死亡,剩下 75% 的樣本期只是在記錄一條水平線。** 平均曝險 0.0478 就是這樣來的。

### 2.1 這個風險我自己標記過,然後沒有防它

[`CP-005`](./proposals/CP-005-risk-policy-for-always-in-market.md) 3.4 節的原文:

> ⚠️ **仍須誠實說明:這個機制的效果未經驗證。** 它不增加自由參數,但它是一個**新機制**,可能有未預期的行為。

**風險說中了,但我列的例子是「反覆調整墊高換手成本」,沒想到更嚴重的是單向鎖死。**

### 2.2 測試為什麼沒抓到

`test_drawdown_ramp_cuts_exposure_in_deep_drawdown` 驗證「深度回撤後曝險應接近 0」—— **它驗證的正是導致死亡的那個行為,而且判定為正確。**

**測試檢查了機制是否照設計運作,沒有檢查設計本身是否合理。** 這是測試覆蓋的一個真實盲點,不是測試寫錯。

## 3. 這兩個錯誤怎麼修,以及代價

### 3.1 錯誤一:純粹的 bug 修正

零技巧基準的**定義**是「產生 MDD = 30% 的固定曝險」。我的公式沒有算出符合這個定義的值。**修正公式讓它符合自己的定義,不是改變規格。**

同樣地,`σ_target` 的定義是「使平均曝險對齊零技巧基準」,修正後為 12.3%。

**我方主張這不消耗 `N`** —— 它不是在候選集合中換一個選擇,而是修正一個算錯的量。**但這個主張應由專案負責人裁決,不由犯錯者自行認定。**

### 3.2 錯誤二:需要新的設計決策,**這會消耗 `N`**

吸收態必須解決,而任何解法都是一個**新的設計選擇**:

| 選項 | 說明 | 代價 |
|---|---|---|
| A | 斜坡改用**滾動視窗**回撤(例如過去 365 天),而非歷史全期 | 引入新參數(視窗長度) |
| B | 設一個曝險下限(例如 `factor ≥ 0.1`),保留恢復能力 | 引入新參數(下限值) |
| C | **移除斜坡**,只保留 40% 的硬性 kill switch(停機需人工恢復) | 零新參數,但失去 CP-005 3.4 節的平滑保護 |
| D | 斜坡改為對**未實現**回撤反應,權益歸零後仍持續追蹤基準 | 語意複雜,實質是重新定義回撤 |

**任一選項都是在看到失敗結果之後做的設計變更,必須誠實計入 `N`。**

⚠️ 我方傾向 **C**(零新參數、最保守、且承認「平滑斜坡」這個想法在這次驗證中沒有成立),但**這是提出者的傾向,不是決定**。

## 4. 必須說清楚的三件事

1. **本次執行不構成對策略二假說的檢定。** 假說預測的是「相同平均曝險下 MDD 更低或保留報酬更高」,而本次執行的平均曝險是 0.0478 對 0.3397 —— **差了 7 倍,根本不是同一個比較**。

2. **修正後重跑會消耗 `N`。** [`strategy-2-hypothesis.md`](./strategy-2-hypothesis.md) 2.3 節已保守認定 `N=10`;加上本次的設計變更,重跑時應提高認定。**具體數字應在重跑之前定案。**

3. **我方不主張「修好就會通過」。** 錯誤一讓曝險偏高、錯誤二讓策略死亡,兩者都往「表現更差」的方向偏 —— 但這**不代表**修正後就會通過。真實的答案還沒被測到。
