## 0. 文件定位與跨小節依賴關係

這份文件不是 5 個互不相干的技術名詞清單,而是一條**單一的驗證管線**:第 3 節算出的有效樣本數 `n_eff` 會直接餵進第 1 節的顯著性公式與第 4 節的 Kelly 分數;第 2 節 walk-forward 產出的樣本外(OOS)報酬序列,是第 1 節「交叉檢查」與第 5 節蒙地卡羅模擬**唯一合法的輸入資料**(不可用 in-sample/hyperopt 優化過的報酬);第 4 節算出的實際部位大小,又反過來決定第 5 節模擬的是「真正會發生的權益曲線」而不是「滿倉理論報酬」。任何一節單獨拿掉,其他節的結論都會失真。

實作上,Freqtrade 本身**不內建** Deflated Sharpe Ratio、block bootstrap、Newey-West 校正,這些都需要在 Freqtrade 的 `backtesting`/`hyperopt` 結果(trade 匯出的 JSON/CSV、hyperopt epoch 紀錄)之上,用獨立的 Python 後處理腳本實作(建議工具:`numpy`/`pandas`/`scipy.stats`/`statsmodels`/`arch.bootstrap`)。這件事會在 Phase 6(`backtest-procedure.md`)具體落地,但**公式與門檻在此定案**,Phase 6 不重新發明。

## 1. 符號與資料定義 / Notation

| 符號 | 定義 |
|---|---|
| `n` | 回測期間的**原始交易筆數**(不是天數) |
| `n_eff` | 校正自相關後的**有效樣本數**(第 3 節) |
| `N` | Hyperopt 實際跑過的參數組合數(trial/epoch 數) |
| `SR_hat` | 用交易報酬序列估計出的 Sharpe ratio(樣本統計量) |
| `SR_daily` | 帳戶**每日 mark-to-market 權益曲線**算出的年化 Sharpe |
| `SR_trade` | **逐筆交易報酬**算出的 Sharpe(未按日曆年化) |
| `γ3` / `γ4` | 交易報酬序列的偏度(skewness)/峰度(kurtosis,非超額峰度,常態分布下 γ4=3) |
| `Φ` / `Φ⁻¹` | 標準常態分布的 CDF / 分位數函數(quantile function) |
| `k` | ATR 停損倍數(策略參數) |
| `f*` | Kelly 最適曝險比例 |
| `c` | 實際採用的 Kelly 分數(fractional Kelly 的 `c`,`c=1` 為 full Kelly) |

**兩種 Sharpe 定義不可混用,這是本文件反覆強調的第一個紀律:**

- **`SR_daily`(對齊 Phase 0 的 20–30% / Sharpe 1.0–1.5 目標)**:用帳戶每日權益曲線報酬計算,年化時用 `× sqrt(365)`(加密貨幣 24/7 交易,**不是**股票市場慣用的 252 個交易日——這是常見但會系統性高估 Sharpe 的錯誤,務必在 Phase 6 的回測報告設定中確認)。這是 Freqtrade backtesting 報告預設輸出的 Sharpe 定義,也是唯一能和「最大回撤」「月回撤熔斷」放在同一個日曆時間軸上比較的指標。
- **`SR_trade`(用於第 1/3/4 節的統計檢定與部位公式)**:用**逐筆交易報酬**計算,觀測單位是「一筆交易」而非「一天」。

**為什麼不能用日曆天數當樣本數做顯著性檢定:** 波段突破策略持倉率(time-in-market)通常遠低於 100%,回測期間大量日子是空手、報酬恰好為 0。若把這些 0 報酬的日子也算進顯著性檢定的樣本數 `n`,會發生兩件事同時成立:(a) 這些天沒有提供任何關於「策略有沒有 edge」的新資訊,因為根本沒有部位在跑;(b) 但把它們計入 `n` 會機械性地放大樣本數、壓低標準誤(`SE ∝ 1/√n`),讓 t 統計量/PSR 看起來比實際更顯著。這是一個容易被忽略但後果嚴重的陷阱——**第 1、3、4 節的 `n`/`n_eff` 一律以「交易筆數」為單位,絕不可用日曆天數替代。**

## 2. 統計顯著性檢定 / Statistical Significance Test

### 2.1 為什麼需要——問題不是「Sharpe 夠不夠高」,而是「找到這個 Sharpe 的過程本身就在製造假訊號」

Freqtrade 的 hyperopt 會對 N、X、M、ATR 週期、ATR 停損倍數這組參數空間做大量嘗試(常見設定是數百到數千個 epoch)。這是**多重比較問題(multiple testing)**的教科書場景:即使策略完全沒有真實 edge、交易報酬純粹是雜訊,只要嘗試夠多組參數,「歷史上表現最好的那一組」的樣本內 Sharpe 幾乎必然顯著大於 0——這正是 [`stable-profitability-roadmap.md`](./stable-profitability-roadmap.md) 中 backtest-analyst 對「Sharpe > 3 高度懷疑」的直覺來源,以及 [`strategy-hypothesis.md`](./strategy-hypothesis.md) 已列為已知風險的「過擬合」。單純看 hyperopt 選出的那組參數的 Sharpe ratio,回答的是錯誤的問題。

需要的是:**在已知「嘗試過 N 組參數」這個事實之後,這個 Sharpe 有多大機率不是純粹靠試出來的運氣?** 這正是 Deflated Sharpe Ratio(DSR,Bailey & López de Prado, 2014)設計來回答的問題。

### 2.2 方法一(主要檢定):Probabilistic Sharpe Ratio → Deflated Sharpe Ratio

**第一步:PSR(單一策略,不考慮多重比較)**

給定一個基準 Sharpe `SR*`,PSR 回答「真實 Sharpe 超過 `SR*` 的機率是多少」:

```
PSR(SR*) = Φ[ (SR_hat - SR*) · sqrt(n_eff - 1)
              / sqrt(1 - γ3·SR_hat + ((γ4-1)/4)·SR_hat²) ]
```

分母是 Sharpe ratio 估計量的漸近標準誤(Mertens, 2002 的公式),它明確把偏度、峰度也納入——這對本策略特別重要,因為趨勢跟隨策略的報酬分布**天生右偏、肥尾**(多數小額停損 + 少數大額趨勢單),用「常態分布假設」的樸素標準誤會低估變異,虛增顯著性。

**第二步:算出「純靠運氣、試 N 次能得到的最佳 Sharpe」當作 `SR*`**

若某個 hyperopt trial 的真實 edge 為 0,`N` 次獨立嘗試裡「最好的那次」Sharpe 期望值(極值分布理論):

```
SR0 = E[max_N{SR_n}] ≈ σ_SR · [ (1-γ)·Φ⁻¹(1 - 1/N) + γ·Φ⁻¹(1 - 1/(N·e)) ]
```

- `γ ≈ 0.5772`(Euler–Mascheroni 常數)
- `σ_SR` = **hyperopt 這 N 次 trial 實際跑出來的 Sharpe ratio 的樣本標準差**(不是理論值,是從 Freqtrade hyperopt 的 epoch 紀錄裡,把每一組參數組合的 Sharpe 全部取出來直接算標準差)——這點很重要,因為它讓這個公式變得**可直接從 Freqtrade 的 hyperopt 輸出實作**,不需要另外假設。

**DSR** 就是把 `SR* = SR0` 代入 PSR:`DSR = PSR(SR0)`。

**數值示例(假設數字,示範方法論,非真實回測結果):**

假設 Phase 6 的 hyperopt 跑了 `N = 1000` 組參數,這 1000 個 Sharpe 的樣本標準差 `σ_SR = 0.35`(年化):

```
Φ⁻¹(1 - 1/1000)        = Φ⁻¹(0.999)     ≈ 3.09
Φ⁻¹(1 - 1/(1000·e))    = Φ⁻¹(0.99963)   ≈ 3.38

SR0 = 0.35 × [0.4228×3.09 + 0.5772×3.38]
    = 0.35 × [1.31 + 1.95]
    = 0.35 × 3.26
    ≈ 1.14
```

**這個數字本身就是重要結論:光是「試過 1000 組參數」這件事,純靠運氣就能生出一個 Sharpe ≈ 1.14 的最佳結果——這已經落在 Phase 0 目標區間(1.0–1.5)裡面。** 換句話說,如果 hyperopt 選出的最佳參數 Sharpe 只是「剛好落在 1.0–1.5」,在還沒扣掉多重比較效應之前,這個數字幾乎不能證明任何事。

再往下算完整 DSR:假設 hyperopt 選出的策略在樣本內 `SR_hat = 1.3`,交易報酬偏度 `γ3 = 0.8`(右偏,符合趨勢策略特性)、峰度 `γ4 = 5`(肥尾),`n_eff = 48`(第 3 節示例):

```
分母 = sqrt(1 - 0.8×1.3 + (5-1)/4×1.3²) = sqrt(1 - 1.04 + 1.69) = sqrt(1.65) ≈ 1.285
分子 = (1.3 - 1.14) × sqrt(48-1) = 0.16 × 6.856 ≈ 1.061

z = 1.061 / 1.285 ≈ 0.826
DSR = Φ(0.826) ≈ 0.80
```

**`DSR ≈ 0.80` 沒有通過 0.95 的門檻。** 一個表面上「符合 Phase 0 目標」的 Sharpe 1.3,扣掉「試了 1000 組參數」與「有效樣本只有 48 筆交易」的雙重折損之後,只有約 80% 的信心真實 edge > 0——這遠不足以拿去實盤。

**反推:在這組假設下,`SR_hat` 需要多高才能通過 `DSR ≥ 0.95`?** 反覆代入求解(`Φ⁻¹(0.95)=1.645`):約在 `SR_hat ≈ 1.48` 才勉強達標——**幾乎是 Phase 0 目標區間(1.0–1.5)的最上緣。** 這是本節最重要的警訊:**在 N=1000、n_eff=48 這種寫實的假設下,Phase 0 訂的 Sharpe 目標區間本身就沒有多少統計餘裕**,樣本內 Sharpe 剛好等於 1.0 或 1.1 這種「勉強達標」的結果,幾乎肯定通不過 DSR。這不是要求 Phase 0 改目標(那是 Phase 0 已拍板的商業/風險決策),而是提醒 backtest-analyst 與專案負責人:**「回測 Sharpe 落在 1.0–1.5 區間」跟「這個 Sharpe 統計上站得住腳」是兩件事,後者的門檻實質上更接近區間上緣。**

**`N` 的敏感度(供 Phase 6 決定 hyperopt 搜尋規模時參考):** `E[max_N SR_n]` 對 `N` 是次線性成長(漸近於 `√(2·ln N)`),`N` 每增加 10 倍,折損係數 `C(N)`(乘在 `σ_SR` 前面的係數)大約只增加 1.2–1.3 倍,不是等比例惡化:

| N(trial 數) | C(N)(乘上 σ_SR 得 SR0) |
|---|---|
| 100 | ≈ 2.54 |
| 500 | ≈ 3.06 |
| 1,000 | ≈ 3.26 |
| 5,000 | ≈ 3.69 |
| 10,000 | ≈ 3.88 |

意思是:hyperopt 從 500 次加到 2000 次不會讓門檻爆炸性升高,但這不代表可以無腦跑十萬次網格搜尋——`N` 越大,搜尋出的「最佳」參數組合本身也越可能只是雜訊的極值,實務上仍建議 Phase 6 用**理論驅動的窄參數範圍**而非盲目寬網格(呼應 [`strategy-hypothesis.md`](./strategy-hypothesis.md) 已列的「過擬合」風險防範)。

> 上述所有 `Φ⁻¹` 數值皆為近似值,僅供手算示範方法論;正式實作**必須**用 `scipy.stats.norm.ppf`/`scipy.stats.norm.cdf` 精確計算,不可用本文件的手算近似值。

### 2.3 已知限制:DSR 假設 N 次 trial 互相獨立,但 hyperopt 網格搜尋不是

DSR 的極值公式假設 N 次嘗試彼此獨立。但 hyperopt 在做的是**網格/連續參數搜尋**——相鄰的參數組合(例如 N=20 天 vs N=21 天的 Donchian 通道)產生的交易訊號高度重疊,對應的權益曲線高度相關,不是獨立樣本。用原始 epoch 數當作 `N` 代入公式,會**高估**多重比較的懲罰(因為真正「不同」的策略遠少於 epoch 數)。

**建議修正:** 在計算 DSR 之前,先對 hyperopt 所有 trial 的**日報酬序列做相關性分群**(例如兩個 trial 的日報酬相關係數 > 0.9 視為同一群),用**分群後的群數**當作 DSR 公式裡的有效 `N`,而不是原始 epoch 數。

### 2.4 交叉檢查:White's Reality Check / Hansen's SPA(建議作為第二道防線)

正因為 DSR 對「trial 之間的相關性」較敏感,建議額外跑一次 **White's Reality Check**(或更穩健的 Hansen's Superior Predictive Ability, SPA test)作交叉驗證。做法(stationary bootstrap):

1. 取 hyperopt 前 K 名候選策略(不只最佳那組)在**同一段樣本外期間**的逐日報酬。
2. 用 stationary bootstrap(見第 3 節的區塊自助法)對「時間」重抽樣 B 次,每次重抽樣後,同時套用到所有 K 個候選策略(保持策略間的同期相關性),計算每次重抽樣中「表現最好的策略」超額報酬。
3. 用這 B 個「最佳表現」的自助分布,估計「觀察到的最佳策略表現,有多大比例是純粹選擇偏誤造成的」——因為重抽樣同時作用在所有候選策略上,天然保留了 trial 之間的相關結構,不需要像 DSR 那樣額外做分群修正。

這個方法計算量較大,不要求每次 hyperopt 都跑,但**在策略要送交 Phase 6 backtest-analyst 最終簽核前必須跑至少一次**作為 DSR 結果的獨立驗證。

### 2.5 通過門檻

- **主檢定:** `DSR ≥ 0.95`(對應約 95% 信心真實 edge 為正,等價於單尾 p < 0.05),用 hyperopt 樣本內結果 + 實際 N(或分群後有效 N)計算。
- **次檢定(獨立防線,不可用同一份資料互相印證):** 對第 2 節 walk-forward 產出、**從未進入過 hyperopt 優化過程**的樣本外(OOS)交易報酬序列,單獨算一次 `PSR(SR*=0)`,一樣要求 `≥ 0.95`。DSR 和這個 OOS 檢定**兩者都要過**,任一失敗即不通過。
- **交叉檢查:** White's Reality Check / SPA 的 p-value `< 0.05`。若與 DSR 結論明顯矛盾(例如 DSR 過了但 Reality Check 沒過),以較保守者(Reality Check)為準,並回頭檢查 hyperopt trial 是否過度相關。

## 3. Walk-Forward 驗證切分規則 / Walk-Forward Validation Split Rules

### 3.1 為什麼波段策略的視窗長度不能照搬日內策略的經驗值

策略一的訊號建立在**日線收盤**(Donchian 突破)之上,持倉常見數天到數週(用 ATR 移動停損才出場)。這代表:

- 突破策略天生交易頻率低——一個乾淨的趨勢市場一年可能才有個位數到十幾次有效突破訊號(單一標的)。視窗太短(例如 1 個月 IS / 1 週 OOS,常見於日內高頻策略的建議),每個 fold 可能連 1 筆交易都不到,無法計算任何統計量。
- 指標本身有記憶:N 日 Donchian 通道、M 日成交量均量、ATR 週期,都需要視窗**遠大於**這些參數的量級才能讓指標穩定,且需要涵蓋足夠長的時間讓「趨勢期」與「盤整期」都出現在 in-sample(IS)裡,hyperopt 才不會只學到單一 regime 的參數。

### 3.2 建議切分

| 項目 | 建議值 | 理由 |
|---|---|---|
| **IS(訓練)視窗長度** | **24 個月**、滾動(rolling,非 anchored) | 24 個月通常涵蓋 2–3 個子週期(牛/熊/盤整交替),足以讓 hyperopt 不會只針對單一 regime 過擬合;採滾動窗而非擴張窗,是因為 [`strategy-hypothesis.md`](./strategy-hypothesis.md) 已標記本策略高度依賴 BTC 大盤 regime——用擴張窗會讓 2017-2019 年的舊資料在權重上越來越稀釋不掉,但那個時期的市場結構(機構化程度、流動性)與現在已有實質差異,滾動窗能避免舊 regime 干擾參數估計。
| **OOS(測試)視窗長度** | **6 個月** | 短到能累積出足夠多 fold(見下),長到能容納突破策略一次完整的訊號-進場-出場週期;6 個月也對齊 Phase 0 的「月回撤 8% 熔斷」時間尺度,方便之後對照。
| **步進(每次滾動前進量)** | **6 個月(等於 OOS 長度)** | 讓各 fold 的 OOS 區間**首尾相接、互不重疊**,才能把所有 fold 的 OOS 交易**直接串接**成一條連續的「模擬實盤」報酬序列,而不是靠平均各 fold 的 Sharpe(對小樣本比率型統計量取平均在統計上並不嚴謹)。
| **Embargo(禁運期)** | **≥ 30 天**,或 `max(指標最大回顧窗, 歷史持倉時間 95th 百分位)`,取兩者較大值 | 見 3.3。
| **Purge(淨化)** | 需要 | 見 3.3。
| **每個 fold 是否重新 hyperopt** | **是,每個 fold 用該 fold 的 IS 資料獨立重跑一次 hyperopt** | 若整個回測期間只跑一次 hyperopt、拿同一組「全局最佳參數」套用到所有 fold,那根本不是 walk-forward,只是一次性的樣本外測試加上好看的名字。**每個 fold 重新優化參數、記錄每次選出的參數是否穩定**,本身就是額外的穩健性訊號——如果每個 fold 選出的 N、X 差異巨大,代表參數對雜訊敏感,是過擬合的警訊。

### 3.3 Purge / Embargo 的具體規則與原因

**問題:** ATR 移動停損可能讓一筆交易持倉數天到數週。如果一筆交易在 IS 視窗結束前**進場**,但出場結果落在 embargo 甚至 OOS 期間內,把這筆交易的績效算進 IS 的 hyperopt 目標函數,等於讓 hyperopt 間接看到了 OOS 早期的資訊(這筆交易的最終盈虧其實是靠 OOS 那段時間的價格走勢決定的)——這是時間序列交叉驗證裡典型的資訊洩漏(López de Prado 的 purged/embargoed K-fold 概念,套用到 walk-forward)。

**規則:**

1. **Purge:** 任何在 IS 視窗最後 `embargo_days` 天內**進場**的交易,一律從 IS 的 hyperopt 目標函數計算中剔除(不是刪掉這筆交易本身,是「不讓 hyperopt 用它的結果來挑參數」)。
2. **Embargo:** IS 視窗結束與 OOS 視窗開始之間,留出至少 `embargo_days` 天的空白期,空白期內的資料兩邊都不使用。
3. `embargo_days = max(N, M, ATR週期) + 持倉天數的 95th 百分位`。若策略一最終參數落在常見範圍(N、M 約 20–55 天,ATR 週期約 14 天,持倉中位數約 1–3 週但尾部可能拉長到 1 個月),`embargo_days` 建議下限抓 **30 天**,實際數字待 Phase 6 用真實回測的持倉時間分布重新校準,但**不得低於 30 天**。

### 3.4 附加檢查:用 CUSUM 偵測結構性斷點(呼應「時間序列平穩性」的要求)

Donchian 通道作用在**價格序列**上,價格本身非平穩(有單位根、會趨勢)是預期之中、不是問題——這是突破策略設計本身依賴的特性,不需要對價格序列做平穩性檢定。**真正需要檢查平穩性的是「交易報酬序列」本身的統計特性(均值、變異數)是否隨時間穩定**,而不是價格。

**做法:** 把每個 walk-forward fold 的 OOS 交易報酬,依時間順序串接成一條序列,對其計算 CUSUM(累積和)統計量:

```
S_t = Σ_{i=1}^{t} (r_i - r̄)  ,  t = 1, ..., n
```

若 `S_t` 在某個時間點附近出現明顯、持續的單向偏移並穿越控制界線(可用 `±k·σ√n` 作為經驗界線,`k` 常取 4–5),代表該時間點前後策略的報酬特性發生結構性改變(例如:2021 年 alt season 表現極佳、2022 熊市持續虧損,兩段接起來看均值差異巨大)。這**不是**自動判定策略失敗,而是提醒:若 CUSUM 偵測到斷點,後續第 1 節、第 3 節、第 5 節的統計量都應該**額外對斷點後的子區間單獨算一次**,而不是只看全樣本平均——全樣本的顯著統計量可能是被斷點前的單一好 regime 撐起來的,斷點後的真實表現可能完全不同。

### 3.5 通過門檻

- **最少 fold 數:5 個**(以 BTC/ETH 現有可用歷史,24mo IS / 6mo OOS / 6mo 步進推算,約可產出 8–12 個 fold,故 5 為底線而非目標)。**目標 8–10 個 fold。**
- **一致性:** 至少 **70% 的 fold** 個別 OOS Sharpe(`SR_trade`,未經 DSR 折算)須 `> 0`。若通過率低於此,代表策略只在少數 regime 有效,不能視為穩健。
- **參數穩定性:** 各 fold 重新 hyperopt 選出的 N、X 須落在同一個數量級內(建議:各 fold 選出值的變異係數 CV = std/mean `< 0.5`);若某個 fold 選出的最佳參數與其他 fold 差異過大,須在報告中標記並排查原因。
- **CUSUM 檢查:** 若偵測到結構性斷點,斷點後子區間必須**獨立**滿足第 1、5 節門檻,不能只靠斷點前的表現拉高全樣本平均後矇混過關。
- **Embargo 合規:** `embargo_days ≥ 30` 且 `≥ max(N,M,ATR週期) + 持倉95th百分位`,這是方法論上的硬性規定,不是統計門檻(未滿足視為驗證程序本身無效,不論績效數字多好看)。

## 4. 有效樣本數校正 / Effective Sample Size Correction

### 4.1 為什麼交易筆數不能直接當作獨立樣本數

策略一是趨勢跟隨,經濟機制是「趨勢一旦形成會延續」([`strategy-hypothesis.md`](./strategy-hypothesis.md))。這個機制本身就意味著**交易報酬會正自相關**,原因有二層:

1. **時間序列上的自相關(單一標的內):** 強趨勢期間,一筆突破交易出場後,價格常常很快再次觸發下一次突破訊號(pyramiding 式的連續進場),這些交易的盈虧高度相關——連續獲利或連續停損傾向於成群出現,而不是獨立事件。
2. **跨標的的同期相關(BTC 與 ETH 之間):** [`strategy-hypothesis.md`](./strategy-hypothesis.md) 已明確標記「三個候選策略都高度依賴 BTC 大盤 regime」。當大盤出現同步性的趨勢或崩跌,BTC 與 ETH 的突破訊號常常在同一週甚至同一天觸發,兩筆「不同標的」的交易在統計上仍是同一個總經事件的兩個面向,不是兩個獨立觀測。

若直接用原始交易筆數 `n` 代入標準誤公式(`SE = σ/√n`,假設 i.i.d.),會系統性低估真實變異數、高估統計顯著性——這正是為什麼第 1 節不能直接用樸素 `n`,必須先在此節算出 `n_eff`。

### 4.2 方法一:Newey-West(HAC)調整 + 有效樣本數公式

**推導:** 對於一個平穩序列,樣本均值的變異數(考慮到自相關)為:

```
Var(r̄) = (σ²/n) × [ 1 + 2·Σ_{l=1}^{n-1} (1 - l/n)·ρ_l ]
```

只在自相關明顯的前 `L` 個 lag 內加總(超過 `L` 假設 `ρ_l ≈ 0`),並用 Bartlett 核權重 `w_l = 1 - l/(L+1)` 保證估計量半正定(這就是 Newey-West 1987 estimator 的標準做法):

```
IF = 1 + 2·Σ_{l=1}^{L} w_l·ρ_l        (IF = inflation factor / 積分自相關時間)

n_eff = n / IF
```

**Newey-West 估計式(可直接實作,用於算穩健標準誤):**

```
Var_NW(r̄) = (1/n²) × [ Σ_t (r_t - r̄)² + 2·Σ_{l=1}^{L} w_l·Σ_{t=l+1}^{n} (r_t - r̄)(r_{t-l} - r̄) ]
```

**Lag 長度 `L` 的選擇:** 用 Newey-West(1994)經驗法則 `L = floor(4·(n/100)^(2/9))` 當起點,再檢查樣本 ACF——若 `ρ_l` 在某個 lag 之前都落在白噪音的 95% 信賴帶(`±1.96/√n`)之外,`L` 至少要涵蓋到 ACF 明顯衰減到帶內為止。

**數值示例(假設數字):** 原始交易筆數 `n = 80`(BTC + ETH 合併,回測期間約 5–8 年),樣本 ACF 估出 `ρ1=0.30, ρ2=0.18, ρ3=0.08`,取 `L=3`,Bartlett 權重 `w1=0.75, w2=0.5, w3=0.25`:

```
IF = 1 + 2×(0.75×0.30 + 0.5×0.18 + 0.25×0.08)
   = 1 + 2×(0.225 + 0.09 + 0.02)
   = 1 + 2×0.335
   = 1.67

n_eff = 80 / 1.67 ≈ 48
```

這就是第 1 節示例中 `n_eff = 48` 的來源——**原始 80 筆交易,校正自相關後只等於約 48 筆獨立資訊量,縮水了 40%。**

**跨標的相關的處理:** 上述 ACF 若直接對「BTC、ETH 交易依時間先後混合排序」的序列計算,已經隱含吸收了一部分跨標的同期相關(因為同期觸發的兩筆交易在序列中會緊鄰,ACF 的 lag-1、lag-2 項會捕捉到)。但這是**近似處理**,更嚴謹的做法是:額外檢查「BTC 進場日期」與「ETH 進場日期」的重疊率,對同一週內同時觸發的 BTC/ETH 交易組,在計算 `n_eff` 前先合併視為一個「聚類」(cluster)觀測,再對「聚類後的序列」做上述 Newey-West 流程。這件事留給 Phase 6 backtest-analyst 用真實交易時間戳實作,本文件只定義原則:**同期觸發的跨標的交易,不得視為兩筆獨立觀測。**

### 4.3 方法二(建議並行,互相驗證):Block Bootstrap

Newey-West 是漸近(asymptotic)估計,在 `n` 只有幾十筆的小樣本下,常態近似可能不準。建議並行跑一個不依賴常態假設的無母數方法:

1. 用 **stationary bootstrap**(Politis & Romano, 1994):每次重抽樣時,以機率 `p` 開始一個新區塊、否則延續目前區塊(區塊長度服從幾何分布,期望長度 `= 1/p`),把 `p` 設為 `1/L̂`(`L̂` 取自 4.2 節估出的自相關衰減長度,例如 `L=3` → `p≈0.33`),重複抽取直到湊滿長度 `n` 的一條偽序列(允許跨越原序列尾端回頭銜接,以維持平穩性)。
2. 重複 `B = 10,000` 次,每次得到一條長度 `n` 的偽交易報酬序列,對每條算一次 `SR_trade`(或直接算 DSR 所需的 `μ`、`σ`、`γ3`、`γ4`)。
3. 得到 `SR_trade` 的**empirical 分布**,直接讀出 2.5%/97.5% 分位數作為 95% 信賴區間,不需要依賴 PSR 公式裡的常態近似。

**Python 實作提示:** `arch.bootstrap.StationaryBootstrap`(`arch` 套件)可直接處理區塊長度的隨機化與抽樣,不需要手刻。

### 4.4 通過門檻

- `n_eff` 與 `IF` 兩者都必須在最終報告中揭露(不能只報告點估計的 Sharpe,不報告校正過程)。
- **`n_eff ≥ 30` 為硬性下限。** 低於這個數字,不論 `SR_hat` 或 DSR 點估計數字多漂亮,都**視為資訊量不足、自動不通過**,不得靠提高信心水準彌補——這通常代表回測期間或標的數量不夠,需要 Phase 6 延長歷史區間或（在不違反 Phase 1「避免山寨幣 beta 污染」的前提下)謹慎評估是否納入更多高流動性標的。
- **`IF > 3`(即 `n_eff < n/3`)須在報告中額外標記為「高度聚類風險」**,即便統計檢定通過,也要提醒這代表策略的獲利高度集中在少數幾段趨勢期,實際運行時很可能出現長時間的平淡期甚至虧損期後才等到下一段趨勢——這是操作面(而非統計面)的風險揭露,呼應 [`strategy-hypothesis.md`](./strategy-hypothesis.md) 對 regime 依賴的既有警示。
- Block bootstrap 給出的 95% CI 下界(`SR_trade` 的 2.5th percentile)必須 `> 0`,作為 Newey-West 漸近估計的獨立交叉驗證。兩個方法結論若矛盾,以 block bootstrap(較不依賴常態假設)為準。

## 5. 倉位大小公式 / Position Sizing Formula

### 5.1 為什麼不能用 Full Kelly

**Kelly 準則的推導(連續報酬近似):** 若每期把資金的比例 `f` 投入一個平均報酬率 `μ`、變異數 `σ²` 的報酬流,資金的期望對數成長率為:

```
g(f) = f·μ - (f²·σ²)/2
```

對 `f` 取極大值:`g'(f) = μ - f·σ² = 0` → **`f* = μ/σ²`**(等價寫法:`f* = SR/σ`,因為 `μ = SR·σ`)。這就是 full Kelly。

**Full Kelly 為什麼危險——不是「風格保守與否」的問題,是數學上的脆弱性:**

`g(f)` 是一條開口向下的拋物線,在 `f = 2f*` 時 `g(f) = 0`,超過 `2f*` 之後 `g(f) < 0`——也就是說**下注超過兩倍最適比例,長期幾何成長率會變成負的,即使邊際期望報酬(算術平均)仍然是正的。** Full Kelly 用的 `f* = μ̂/σ̂²` 是把「估計值」當「已知真值」代入,但 `μ̂` 是用僅僅 `n_eff`(第 3 節校正後,常態情境下可能只有 30–50 這個量級)筆有效觀測估計出來的,標準誤不小。只要 `μ̂` 因抽樣誤差偶然超估真實 `μ` 達到 2 倍以上(在小樣本下這不是小機率事件),照 full Kelly 下注就已經進入 `g(f)<0` 的區域——**主觀上以為自己在用「已驗證的正 edge」下注,數學上實際卻在虧錢的區間裡加碼**,這正是 full Kelly 對噪音 edge 特別脆弱、容易爆倉的機制,而不是空泛的「風險偏好」問題。這也直接呼應 [`stable-profitability-roadmap.md`](./stable-profitability-roadmap.md) 中 quant-mathematician 角色原始提出的立場。

### 5.2 建議方案:Quarter-Kelly(`c = 0.25`),疊加 ATR 換算成實際下單量

**Fractional Kelly 的成長率/風險取捨(推導):** 若實際下注比例為 `f = c·f*`(`0 < c ≤ 1`):

```
g(c·f*) = c·f*·μ - (c·f*)²·σ²/2 = (μ²/σ²)·(c - c²/2) = g(f*)·(2c - c²)
```

即 fractional Kelly 能拿到 full Kelly 成長率的 `(2c - c²)` 比例,而下注比例(進而言之,權益曲線的波動與最大回撤量級)是線性地隨 `c` 縮小:

| `c` | 拿到的成長率比例 `(2c-c²)` | 下注比例(相對 full Kelly) |
|---|---|---|
| 1.00(full） | 100% | 100% |
| 0.50(half) | 75% | 50% |
| 0.25(quarter) | 43.75% | 25% |
| 0.10 | 19% | 10% |

**Quarter-Kelly 用 25% 的下注規模拿到近 44% 的理論成長率,同時把「估計誤差把你推進 `g(f)<0` 區域」的緩衝空間放大到 4 倍**(因為現在要 `μ̂` 高估真實 `μ` 達 8 倍(`2×f*/c=2×4=8` 倍原本的 `f*`),才會讓 `g(c·f*)` 變負,而非 full Kelly 情境下只要高估 2 倍就出事)。這是本文件建議 **`c = 0.25` 作為基準 fractional Kelly** 的量化依據,而非只是「業界常見做法」的引用。

**把 `f*` 換算成實際 ATR 停損下的部位大小:** 策略一的每筆交易風險由 ATR 停損距離定義(`k × ATR`)。若 `f`(佔權益比例)全部曝險在一筆交易上,一旦觸及停損,實際虧損佔權益的比例:

```
risk_fraction = f × (k·ATR / entry_price) = f × k × ATR%
```

**下單量公式(對接 Freqtrade 的 stake amount 邏輯):**

```
position_size(base currency) = (risk_fraction × Equity) / (k × ATR_in_quote_currency)
```

這與 [`stable-profitability-roadmap.md`](./stable-profitability-roadmap.md) 中 risk-manager 原本提出的「依 ATR 動態換算部位」做法完全相容——差別在於,**`risk_fraction` 不再是拍腦袋訂的「1–2%」,而是由 Kelly 分析回推出來、有數學依據的上限**,Phase 4 risk-manager 仍握有最終決定更保守數字的權力,但不會是無憑無據的猜測。

**數值示例(假設數字,呼應第 1、3 節的假設情境):** 樣本外估計的策略在場年化 Sharpe `SR_1 = 1.1`(注意:用 OOS 估計值,不是 in-sample optimized 值),在場年化波動度 `σ_1 = 35%`,`k = 3`,ATR 約為價格的 `3%`(BTC 常見日 ATR 量級):

```
f* = SR_1/σ_1 = 1.1/0.35 ≈ 3.14        （full Kelly 隱含要用 3.14 倍槓桿——本專案現貨無槓桿,凸顯 full Kelly 在此完全不可行）

c=0.25 → 目標曝險比例 = 0.25×3.14 ≈ 0.786（78.6% 權益）

risk_fraction = 0.786 × 3 × 3% ≈ 7.07%   （單筆停損虧損佔權益 7.07%）
```

**這個結果本身就是一個重要警訊:即使套用 quarter-Kelly,換算出來的單筆風險(7.07%)仍然遠高於一般建議的 1–2%。** 這說明對本策略(高波動標的、寬 ATR 停損)而言,**quarter-Kelly 本身還不夠保守,必須再疊加一層絕對風險上限(hard cap)**,兩者取較小值:

```
最終 risk_fraction = min( 0.25 × f* × k × ATR% ,  Phase 4 硬上限,例如 2% )
```

在上例中,`min(7.07%, 2%) = 2%`——**硬上限才是實際生效的約束**,Kelly 分析在這裡的角色從「決定倉位」降級為「上限檢查與未來調整的參照基準」:若未來 Phase 4 考慮放寬硬上限,quarter-Kelly 換算值(此例中 ≈7%)提供了一個「即使放寬,也不該超過這裡」的數學上界,`c` 絕不能超過 0.5(下一段說明)。

### 5.3 硬性規則

- **`c ≤ 0.5` 是任何情況下都不可違反的硬上限**(half-Kelly 本身在多數量化實務中已被視為偏激進的上限,見上表:c=0.5 只拿到 75% 成長率卻要承擔 50% 的下注規模與相應的回撤波動放大)。
- **`c = 0.25`(quarter-Kelly)為預設值**,實際採用的 `risk_fraction` 一律取 `min(quarter-Kelly 換算值, Phase 4 硬上限)`。
- **Full Kelly(`c=1`)一律視為不通過(automatic fail),不需個案評估**——理由見 5.1,這是結構性風險而非需要用回測數字驗證的假設。
- Kelly 公式裡的 `μ`(或 `SR_1`)輸入值,**必須使用第 2 節 walk-forward 的樣本外估計值,並取第 4 節 block bootstrap 信賴區間的下界(悲觀估計),不得使用 hyperopt 優化過的樣本內數字**——這是把「edge 是估計值、不是已知量」的原則具體化到公式輸入層級,而不只是停在「用 fractional 而非 full」這句口號。
- `f*`、`c·f*`、換算後 `risk_fraction`、以及最終取 `min()` 後的結果,四個數字都要在報告中並列揭露,任何一步的取捨都要看得見計算過程。

## 6. 回撤機率估計 / Drawdown Probability Estimation(Monte Carlo)

### 6.1 為什麼要模擬,不能只看回測的歷史最大回撤

單一歷史回測路徑只是「實際發生過的其中一種樣本路徑」。相同的交易報酬分布,若交易發生的**先後順序**不同,權益曲線的最大回撤可以差異很大(例如:連續 5 筆虧損發生在早期 vs. 分散在整個回測期間,對 MDD 的影響完全不同)。歷史回測的單一 MDD 數字,無法回答「這個策略未來實際運行時,遇到比歷史更差的虧損連續發生順序的機率有多高」——這正是 Phase 0 的「月回撤 8% 熔斷」「最大回撤 15–20%」這兩個風控紅線需要一個**機率**而非單一歷史數字來對照。

### 6.2 方法:Block Bootstrap 蒙地卡羅模擬(保留自相關結構)

**為什麼不能用普通(i.i.d.)bootstrap:** 若直接對交易逐筆獨立重抽樣(shuffle),會打散第 3 節已經指出的自相關結構(獲利/虧損成群發生的特性),得到的模擬回撤分布會**系統性低估**真實回撤風險(因為打散後,原本會連續發生的虧損被稀釋分散開來)。**必須用區塊重抽樣**,與第 3、4 節使用同一套區塊長度設定(`p = 1/L̂`,`L̂` 取自第 4 節估出的自相關衰減長度),確保「連續虧損群聚」這個真實存在的風險特性被保留在模擬路徑中。

**具體步驟:**

1. 輸入:第 2 節 walk-forward 產出的**樣本外**交易報酬序列(含每筆交易的持倉天數/時間戳,用於後續重建帶日曆刻度的權益曲線),以及第 5 節算出的**最終實際部位大小**(`risk_fraction`)——模擬的是「真正會被執行的權益曲線」,不是理論滿倉曲線,這一步把第 5 節的結果直接餵進來。
2. 用 stationary bootstrap,對(報酬, 持倉天數)成對的區塊做重抽樣,拼出一條長度相當於 **1 年份**預期交易次數(用歷史交易頻率估計,例如年均 30–50 筆)的偽交易序列。
3. 依重抽樣出的交易序列與持倉天數,重建一條**帶日曆刻度**的權益曲線(這一步是為了能算出「月度回撤」,不只是「交易序次上的回撤」)。
4. 對這條偽權益曲線計算:全期最大回撤(MDD)、任一自然月內的最大回撤。
5. 重複步驟 2–4 **`B = 10,000` 次**(最低不少於 5,000 次)。
6. 彙整 `B` 條路徑的 MDD 分布與月度回撤分布。

**Python 實作提示:** `arch.bootstrap.StationaryBootstrap` 搭配自訂的 `func` 回傳 MDD;或直接寫迴圈搭配 `numpy` 向量化計算 running max drawdown(`equity_curve / np.maximum.accumulate(equity_curve) - 1`)。

### 6.3 輸出與解讀(示意數字,非真實回測結果,僅示範報告該長什麼樣子)

| 指標 | 示意數值 | 對照 Phase 0 |
|---|---|---|
| 模擬 MDD 中位數 | 11% | — |
| 模擬 MDD 95th percentile | 19% | 接近 15–20% 上限 |
| `P(全年 MDD > 20%)` | 6% | 對照「最大回撤上限 15–20%」的硬上限 |
| `P(全年 MDD > 15%)` | 22% | 對照風控熔斷線(見 `stable-profitability-roadmap.md` 中 risk-manager 提出的 -15% kill switch) |
| 預期每年觸發「月回撤 8%」暫停次數 | 1.4 次/年 | 對照 Phase 0 的月回撤熔斷機制 |

**信賴區間揭露:** 由於底層有效樣本數 `n_eff` 偏小(第 4 節,量級 30–50),上述機率估計本身也帶有相當大的不確定性,建議額外報告這些機率估計值的 bootstrap 信賴區間(例如對 `P(MDD>20%)` 這個機率本身,再做一層 bootstrap 或直接看 `B` 次模擬中的二項分布信賴區間),**誠實揭露「機率估計本身也有誤差」,不要用單一點估計數字製造虛假的精確感。**

### 6.4 通過門檻

- **`P(全年 MDD > 20%) ≤ 5%`**:對齊 Phase 0 最大回撤上限的硬上限(15–20% 區間的上緣),模擬路徑中觸破這條線的機率必須壓在 5% 以內,否則代表策略在現實運行中有超過 1/20 的年份會實質違反 Phase 0 的風控紅線。
- **`P(全年 MDD > 15%) ≤ 20–25%`**:15% 是 [`stable-profitability-roadmap.md`](./stable-profitability-roadmap.md) 中 risk-manager 提出的 kill switch 觸發線下緣,這條線被觸發應該是「偶爾發生的極端年份」而不是「常態」——機率上限抓在 20–25%,大約等於「每 4–5 年觸發一次」的量級,若高於此,代表 kill switch 會頻繁跳機,系統形同無法穩定運行。
- **預期每年觸發月回撤暫停(-8%)次數 `≤ 2–3 次/年`**:超過這個頻率,即使技術上沒有違反任何硬性回撤上限,也代表系統在操作面上會頻繁進入「強制停機複查」狀態([`scope.md`](./scope.md) 已定義的治理機制),實務上不可運行。
- **模拟路徑數 `B ≥ 5,000`(目標 10,000)**,且必須明確揭露機率估計值本身的信賴區間寬度,不能只報一個點估計。
- 模擬必須使用**第 5 節最終確定的實際部位大小**(`min()` 之後的 `risk_fraction`),使用未經 Kelly/硬上限約束的滿倉理論報酬跑模擬,一律視為方法論錯誤、結果不採用。

## 8. 已知限制與交棒事項

- 本文件所有數值示例(`σ_SR=0.35`、`n=80`、`ρ_l`、`SR_1=1.1`、`σ_1=35%`、MDD 機率表等)**皆為方法論示範用的假設數字,不是任何真實回測的結果**——真實數字要等 Phase 6 backtest-analyst 用 Freqtrade 實際跑出歷史交易與 hyperopt 結果後才能代入本文件的公式重新計算。
- DSR 對 hyperopt trial 間相關性的敏感度(2.3 節)是本方法論中最需要 Phase 6 落地時特別小心處理的一步,建議 `backtest-procedure.md` 明確寫出「trial 分群」的具體演算法與相關係數門檻,不要含糊帶過。
- 跨標的(BTC/ETH)同期相關的 `n_eff` 修正(4.2 節)目前只給出原則,具體聚類演算法留給 Phase 6 依實際交易時間戳實作。
- 本文件的 Kelly 分析(第 5 節)只處理**單一策略、單一部位方向(做多)**的情境;若未來 v2 納入策略二/三或允許同時持有多筆部位,f* 的推導需要擴充為多資產 Kelly(涉及部位間協方差矩陣),屆時需回頭修訂本文件或另立附錄,現階段不在範圍內。
