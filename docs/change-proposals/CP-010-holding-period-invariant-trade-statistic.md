## 0. 一句話

**`SR_trade` 不是持倉期不變量:任何讓持倉變長的出場規則都會機械性地推高它。** 因此「`SR_trade` 高於某個基準值」這種形式的可證偽預測,無法區分「決策品質變好」與「單純抱得比較久」——本提案要求未來的預測改用具備持倉期不變性的陳述方式,並在配對比較中強制報告兩臂的持倉期。

---

## 1. 問題

[`strategy-5-hypothesis.md`](../strategy-5-hypothesis.md) §2 的第 3 項可證偽預測寫的是:

> 3. **`SR_trade` 高於 0.1723**(1、2 的淨效果;若最大不利偏移(MAE)惡化幅度抵銷了持有更久的好處,此預測不成立)

同一節第 1 項預測則是「平均持倉天數顯著拉長」。

**這兩項預測不是獨立的。** 若交易報酬近似為 iid 增量在持倉期上的加總,則平均值隨持倉期 `T` 線性成長、標準差隨 `√T` 成長,於是

```
SR_trade = mean / std  ∝  T / √T  =  √T
```

**預測 1 成立,幾乎就保證預測 3 成立。** 一個「把停損放寬到永遠不觸發」的退化出場規則會同時滿足這兩項預測,卻顯然沒有改善任何決策品質。這代表預測 3 在方法上接近不可證偽。

[`strategy-5-hypothesis.md`](../strategy-5-hypothesis.md) §2 末的「次要、非否證性觀察」有注意到持倉變長會壓低 `n_eff`、推高門檻,但把這個效應定位成**代價**(讓檢定變難),沒有看出它同時也是**預測 3 本身的混淆項**(讓預測變容易)。兩件事方向相反,不能互相抵銷。

## 2. 證據:策略五的實測數字與 `√T` 縮放一致到 2.3%

| 平均獲利 | +14.43% | +41.93% | — |
| 平均虧損 | −7.51% | −11.02% | — |
| **平均交易報酬**(由上三列導出) | **+2.297%** | **+12.172%** | 5.299 |

SR_trade 比值 = 1.5119
√(T̄ 比值)    = 1.4780

做持倉期正規化後:

| | `SR_trade / √T̄` |
|---|---|

**兩條互相獨立的線索得到一致答案,是本提案的證據基礎。**

## 4. 變更內容

### 4.1 可證偽預測的陳述方式(強制)

**未來任何策略的 Phase 1 假說文件,不得以原始 `SR_trade` 與另一策略的 `SR_trade` 直接比大小作為可證偽預測。** 必須改用下列任一形式:

- **(a) 配對比較的 `delta`**(推薦):控制進場點相同,`delta` 本身已是同一批交易上的差異;但仍須依 4.2 節報告兩臂持倉期。
- **(b) 持倉期正規化統計量** `SR_trade / √T̄`,並同時報告未正規化的原始值與 `T̄`。

若某假說有正當理由必須用原始 `SR_trade`,須在該文件中明文論證為何持倉期混淆在該情境下不成立,不得沉默略過。

### 4.2 配對比較的報告內容(強制)

[`analysis/paired_trade_comparison.py`](../../analysis/paired_trade_comparison.py) 的 `paired_trade_test()` 回傳值必須新增三個欄位:

| 欄位 | 內容 |
|---|---|
| `mean_holding_days_baseline` | 對照組在配對子集上的平均持倉天數 |
| `mean_holding_days_treatment` | 處理組在配對子集上的平均持倉天數 |
| `delta_normalized` | `sr_treatment/√T̄_treatment − sr_baseline/√T̄_baseline` |

`delta_normalized` 是**診斷欄位,不是通過判準**——`passes` 的定義維持現狀(`delta ≥ min_detectable_delta` 且 `n_eff ≥ 30`),本提案不改變通過門檻本身。理由見 4.3。

### 4.3 為什麼不把 `delta_normalized` 直接當成通過判準

因為正確的正規化沒有一個乾淨的答案,而在沒想清楚之前就換判準,只是把一個有瑕疵的統計量換成另一個:

- 用 `SR_trade/√T̄`(全體平均持倉)是**近似**:它假設配對子集內所有交易的持倉期同質,實際上持倉期本身有分佈。
- 改成逐筆正規化 `r̃ᵢ = rᵢ/√Tᵢ` 也不對:若 `rᵢ ~ N(μTᵢ, σ²Tᵢ)`,則 `r̃ᵢ ~ N(μ√Tᵢ, σ²)` ——變異數被拉平了,但**平均數仍隨 `√Tᵢ` 成長**,混淆項沒有消失,只是換了位置。
- 改成年化 `SR_trade × √(每年交易筆數)` 又是另一個答案:策略一 `0.1723×√8.48 = 0.502`、策略五 `0.2605×√7.14 = 0.696`,得出「策略五好 39%」——與正規化版本的 +2.3% 差距極大,因為它把「空手期間視為無風險」這個假設也算了進去。

**三種正規化給出 +2.3%、+39%、以及配對比較的「不顯著」三個不同的印象。** 這正是為什麼本提案的立場是**強制揭露而非替換判準**:讓 `T̄` 與 `delta_normalized` 出現在每一份報告裡,任何人都能自行判斷某個 `SR_trade` 差異有多少來自決策品質、多少來自持倉期;而正式的通過與否,仍由已定案、已實作、已被測試鎖住的配對比較 `delta` 決定。

### 4.4 實作與測試

- `paired_trade_test()` 新增 `holding_days_baseline` / `holding_days_treatment` 兩個輸入參數(逐筆持倉天數陣列),與現有的報酬陣列同長度、同順序。
- 為向後相容,兩者預設 `None`;為 `None` 時三個新欄位回傳 `None`,`passes` 行為完全不變。
- 新增測試:(i) 給定人工資料驗證三個新欄位的數值;(ii) 驗證 `None` 輸入時舊行為逐欄位不變(回歸鎖定);(iii) 驗證持倉天數含 0 或負值時明確拋錯(fail closed,呼應 [`security-policy.md`](../security-policy.md) §5.2 輸入合理性檢查)。

## 5. 為什麼這個變更在預先登錄紀律下是正當的

`CLAUDE.md` 的預先登錄原則禁止「看到結果才回頭改方法」。本提案通過這道檢驗,理由有三:

1. **變更的來源是已 commit 的公開數字,不是新的回測。** §2 的全部輸入取自 [`strategy-5-results.md`](../strategy-5-results.md) §1.1 的表格,沒有重跑任何東西、沒有看任何尚未公布的資料。
2. **變更讓檢定變嚴,不變鬆。** 它增加了強制揭露欄位、限縮了可證偽預測的可用形式,沒有降低任何門檻。一個「看到結果回頭改方法」的變更,其特徵是讓自己更容易通過;本提案的方向相反。
3. **變更不追溯改判。** §3 已明列所有既有判定不受影響,策略五仍然是不通過。本提案唯一的受益者是尚未執行的未來策略,而它們受到的是更嚴格的約束。

**但仍須誠實承認:** 本提案是在策略五失敗之後才寫的。若策略五通過了,我們會不會同樣熱心地去質疑那個 `SR_trade` 提升?**不確定。** 這是不對稱審查的風險,無法用論證消除,只能記錄在此。降低這個風險的唯一方法是本提案的約束對「未來所有策略」一律適用,不論結果方向——第 4 節已如此寫定。

## 6. 誠實揭露

- **§2 的 `√T` 一致性是兩個資料點的比值觀察,不是統計檢定。** 1.512 vs 1.478 差 2.3% 看起來很接近,但 `n=1` 的比較無法排除巧合。它的作用是**提出混淆項存在的機制性理由**(§1 的推導才是主要論證),不是證明策略五的改善「精確等於」`√T`。
- **`SR_trade` 的隱含標準差是反推的**(平均報酬 ÷ `SR_trade`),不是從逐筆交易報酬直接計算。若 [`strategy-5-results.md`](../strategy-5-results.md) 的 `SR_trade` 定義與「平均報酬/報酬標準差」有任何差異(例如扣除無風險利率),反推值會有偏差。已查 [`analysis/`](../../analysis/) 的既有實作為 `mean/std`,無無風險利率項,但這一點未逐行覆核。
- **§1 的 `mean ∝ T`、`std ∝ √T` 推導假設交易報酬是 iid 增量的加總。** 真實價格有自相關與波動度叢聚,兩者都會讓 `std` 的成長偏離 `√T`。這個推導提供的是**量級直覺與混淆項存在性**,不是精確的縮放律。
- **策略五配對子集(57 筆)的兩臂平均持倉天數未在 [`strategy-5-results.md`](../strategy-5-results.md) 公布**,因此無法算出策略五配對比較的 `delta_normalized`。若要補上這個數字,須重跑 [`run_strategy5_evaluation.py`](../../analysis/tools/run_strategy5_evaluation.py) 取出持倉期欄位——這是**讀取一次已公布判定的既有輸出,不是新的檢定**,不改變策略五的結論,但仍應在執行前明文說明目的,避免與「重測」混淆。本提案不強制執行這一步。
- 本提案未經 `backtest-analyst`、`quant-strategist` 審閱。
