## 0. 一句話總結

**[`statistical-methodology.md`](../statistical-methodology.md) 2.2 節的數值示例(以及據以推導的 [`CP-001`](./CP-001-hyperopt-epochs.md) 門檻表)把「年化 Sharpe」與「以交易筆數計的 `n_eff`」混用,違反了同一份文件第 1 節自己訂下的「兩種 Sharpe 定義不可混用」紀律。單位修正後,DSR 通過門檻從年化 1.38 上升到 2.5–4.7,遠高於 [`scope.md`](../scope.md) 的 1.0–1.5 目標。**

## 1. 問題的發現經過

實作 MinTRL([`literature-review.md`](../literature-review.md) 5.1 節建議、已於 commit `f461fe7` 完成)時,第一次試算得到「約 5 筆交易就能證明 Sharpe 0.8」這種明顯荒謬的結果。追查原因後發現不是 MinTRL 實作錯誤(該實作有反解回代測試把關),而是**我方餵進去的 Sharpe 用錯了時間單位**。

進一步檢查發現,**同樣的單位錯誤早已存在於 [`statistical-methodology.md`](../statistical-methodology.md) 2.2 節的數值示例中,並且被 [`CP-001`](./CP-001-hyperopt-epochs.md) 第 2.1 節的門檻表完整繼承。**

---

## 2. 問題的技術本質

### 2.1 PSR 公式的單位要求

```
PSR(SR*) = Φ[ (SR_hat - SR*) · sqrt(n_eff - 1)
              / sqrt(1 - γ3·SR_hat + ((γ4-1)/4)·SR_hat²) ]
```

分母是 Mertens (2002) 的 Sharpe 估計量漸近標準誤。這個公式成立的前提是:**`SR_hat`、`γ3`、`γ4` 全部是「每一個觀測」的統計量,而 `n_eff` 是那些觀測的個數。三者必須指涉同一種觀測單位。**

[`statistical-methodology.md`](../statistical-methodology.md) 第 1 節已經明確規定本專案的觀測單位是**交易筆數**,並且用了一整段說明為什麼不能用日曆天數(持倉率遠低於 100%,空手日不提供 edge 的資訊卻會機械性放大 `n`)。**這條規定是對的,問題出在 2.2 節的示例沒有遵守它。**

### 2.2 混用造成的偏誤方向:高估顯著性

年化 Sharpe 約為 `SR_trade × sqrt(年交易筆數)`。以年交易 30 筆計,把年化值代入公式會讓分子放大約 5.5 倍,而分母只受到部分抵銷,淨效果是 **z 統計量被高估約 8 倍**。

方向很明確:**這個錯誤讓策略看起來比實際更顯著,因此推導出的通過門檻偏低——是偏寬鬆,不是偏嚴格。**

> 補充:`γ3=0.8`、`γ4=5` 這組偏度/峰度是「逐筆交易報酬」的分布形狀(趨勢策略多數小額停損 + 少數大額趨勢單)。把它們和年化 Sharpe 並列,是同一個不一致的第二重表現。

### 2.3 為什麼不能改用「年化 Sharpe + 以天數計的 n_eff」來修

這是理論上另一條可行的修法(全部改成日報酬單位),但**本專案不能採用**:[`statistical-methodology.md`](../statistical-methodology.md) 第 1 節已論證用日曆天數會虛增樣本數、壓低標準誤。**用交易單位是本專案唯一自洽的選擇**,所以本提案主張修正的是示例與門檻表,不是第 1 節的規定。

## 3. 修正後的門檻(數字)

以下用 `analysis/significance.py` 實算。「原表」欄位已成功複現 CP-001 的數字,確認我方正確識別了其計算方式。

**假設:** 偏度 0.8、峰度 5、年交易 30 筆、`DSR ≥ 0.95`。

| `n_eff` | N=100 | N=200 | N=500 | N=1,000 |
|---|---|---|---|---|
| **CP-001 原表(單位混用)** | | | | |
| 30 | 1.27 | **1.38** | 1.51 | 1.60 |
| 50 | 1.17 | 1.26 | 1.38 | 1.47 |
| **修正後,`σ_SR = 0.064`**(把原假設的年化 0.35 換算成交易單位) | | | | |
| 30 | 2.42 | **2.50** | 2.61 | 2.68 |
| 50 | 2.07 | 2.15 | 2.25 | 2.32 |
| **修正後,`σ_SR = 0.197`**(整合測試實測的交易單位值) | | | | |
| 30 | 4.41 | **4.70** | 5.06 | 5.32 |
| 50 | 3.98 | 4.26 | 4.60 | 4.85 |

> 修正後的數字已從 `SR_trade` 換算回年化(`× sqrt(30)`),以便與 [`scope.md`](../scope.md) 的目標直接比較。
>
> ⚠️ **`σ_SR = 0.197` 來自整合測試,該次執行用的是合成/stub 資料,不是真實市場資料,因此這個數值不能當作真實 `σ_SR` 的估計,只能說明「實測值可能比 0.064 大一個數量級」這件事的量級。真實 `σ_SR` 要等 Pass B 跑完 200 個 epoch 才知道。**

### 3.1 補充:`σ_SR = 0.35(年化)` 這個假設另有一個獨立的問題

除了單位之外,原假設值本身在數值上也不成立。參數搜尋結果的 Sharpe 離散度**不可能低於純雜訊**——若 `n_eff` 個觀測下 Sharpe 估計量的標準差是 `sqrt(D/n_eff)`,那就是 `σ_SR` 的物理地板:

| 來源 | `σ_SR`(交易單位) |
|---|---|
| 純雜訊地板(`n_eff≈36`) | **0.167** |
| 整合測試實測值 | 0.197(比地板高 18%,量級吻合) |
| CP-001 假設的 0.35(年化)換算 | **0.064 ← 低於地板,不可能** |

也就是說,`σ_SR = 0.35(年化)` 即使單位對了也是一個**物理上達不到**的樂觀假設。詳見 [`feasibility-paths.md`](../feasibility-paths.md) 第 1.2 節。

### 3.2 這代表什麼

[`CP-001`](./CP-001-hyperopt-epochs.md) 第 2.1 節指出的問題是「門檻 1.60 高於 Phase 0 目標 1.0–1.5」,並透過降低 epochs 把門檻壓到 1.38。**單位修正後,真正的門檻是 2.5–4.7 —— CP-001 解決的是一個算錯的數字,而真實的落差比當時認知的大得多。**

**降低 epochs 這個手段本身沒有失效**(CP-001 第 2.2 節「減少搜尋次數就是減少過擬合機會」的論證與單位無關,仍然正確),但它的**效果量遠不足以彌補真實落差**:N 從 1,000 降到 200 只讓門檻降約 7%,而落差是數倍。

## 4. MinTRL 的獨立佐證

用單位一致的 MinTRL 反查「要證明這個 Sharpe 需要多少樣本」,得到同方向的結論(信心 95%、`SR*=0`、偏度 0.8、峰度 5、`IF=1.67`):

| 目標年化 Sharpe | 需要 `n_eff` | 需要原始交易筆數 | **需要年數** |
|---|---|---|---|
| 0.80 | 115.7 | 193 | 6.4 |
| 1.00 | 73.0 | 122 | 4.1 |
| 1.25 | 46.2 | 77 | 2.6 |
| 1.38 | 37.7 | 63 | 2.1 |
| 1.50 | 31.9 | 53 | 1.8 |
| 2.00 | 18.1 | 30 | 1.0 |

**一個反直覺但重要的結果:「需要年數」幾乎與交易頻率無關。** 因為 `SR_trade² ∝ 1/年交易筆數`,所需交易筆數與頻率成正比,兩者剛好抵銷。**這否定了「提高交易頻率就能更快取得統計顯著性」的直覺——在年化 Sharpe 不變的前提下,交易更頻繁不會讓策略更快被證明。**

### 4.1 對現行 fold 設計的檢查

拿上表和 [`backtest-procedure.md`](../backtest-procedure.md) 4.3/4.4 節的實際樣本量對照(年交易 30 筆、年化 SR=1.38、需求 `n_eff` = 37.7):

| 資料段 | 長度 | 原始交易 | `n_eff` | 對照需求 |
|---|---|---|---|---|
| 單一 fold OOS | 6 個月 | 15 | 9.0 | ❌ 遠遠不足 |
| **單一 fold IS(主檢定 DSR 用)** | 24 個月 | 60 | **35.9** | ❌ **勉強不足(37.7)** |
| 9 fold 串接 OOS(次檢定用) | 54 個月 | 135 | 80.8 | ✅ 足夠 |

兩點觀察:

1. ✅ **[`backtest-procedure.md`](../backtest-procedure.md) 4.4 節把次檢定放在「9 fold 串接後的完整 OOS 序列」的設計是正確的**,MinTRL 定量證實單一 fold OOS(`n_eff≈9`)不可能單獨達到顯著。這是既有設計被驗證,不是被推翻。
2. ⚠️ **但主檢定 DSR 用的單一 fold IS(`n_eff≈35.9`)恰好卡在需求邊緣之下**,且此處的需求還是用寬鬆的 `SR*=0` 算的;DSR 實際用的 `SR* = SR0 > 0`,真實需求只會更高。**主檢定在設計上就是檢定力不足的。** 這一點是 4.4 節「`n_eff` 可能貼近 30 下限」預警的定量版本。

## 5. 提議的變更內容

本提案**只主張修正計算方式,不主張放寬或收緊任何門檻的意圖**。`DSR ≥ 0.95`、`n_eff ≥ 30` 這兩個門檻值本身不變。

1. **修正 [`statistical-methodology.md`](../statistical-methodology.md) 2.2 節數值示例**,明確標註 `SR_hat` 與 `σ_SR` 均為 `SR_trade` 單位,並加註「與第 1 節單位定義一致性」的檢查提醒。
2. **`σ_SR` 的取值方式明確化:** 依 [`backtest-procedure.md`](../backtest-procedure.md) 4.3 節步驟 2,pipeline 匯出的本來就是 `(params, SR_trade)` 表,**實作端已經是對的**,只是文件示例用了年化的假設值 0.35。改為明訂「`σ_SR` 一律取自 epoch 紀錄中 `SR_trade` 的樣本標準差,不得代入年化假設值」。
3. **在 [`CP-001`](./CP-001-hyperopt-epochs.md) 加註**,說明其第 2.1 節門檻表的數字受本提案影響,但其降低 epochs 的決策論證不受影響、維持有效。
4. **不修改** [`scope.md`](../scope.md) 的 Sharpe 目標區間。目標是商業期望,門檻是統計檢定,兩者不匹配是需要被看見的事實,**不應該靠調整任一端來讓它們在紙面上相容**。

## 6. 明確不建議的做法

以下幾條技術上可行,但**本提案明確不建議**,列出以免日後被當成「順理成章的下一步」:

- ❌ **放寬 `DSR ≥ 0.95` 到 0.90 或更低。** 這是在看到門檻算錯、且錯的方向是「原本太寬鬆」之後去調鬆標準,與 [`CP-001`](./CP-001-hyperopt-epochs.md) 第 3 節、[`literature-review.md`](../literature-review.md) 5.3 節的預先登錄原則直接衝突。
- ❌ **改用日曆天數當 `n_eff`。** 見 2.3 節。
- ❌ **下修 [`scope.md`](../scope.md) 的 Sharpe 目標讓它落在門檻之上。** 這是把商業目標去遷就統計工具,因果顛倒。
- ❌ **因為主檢定檢定力不足,就改拿 9 fold 串接 OOS 序列來當主檢定。** 那條序列的樣本數確實夠,但它不能回答主檢定的問題(「即將採用的這組參數,考慮到試出它的過程,有多大機率不是運氣」)——DSR 需要配對的 `N` 與 `σ_SR`,串接序列沒有對應的單一參數搜尋過程。**這個替換會讓數字變好看,但答非所問。**

## 8. 誠實揭露

- **這是我方自己的錯誤,不是外部發現。** 單位混用是我方在 Phase 2 撰寫 [`statistical-methodology.md`](../statistical-methodology.md) 2.2 節示例時引入,並在 CP-001 中沿用。第 1 節的規定寫對了,示例沒有遵守——**規定與示例不一致時,先前是示例贏了**,這正是本次要修正的。
- **Mertens (2002) 標準誤公式的原文我方未取得**(網路政策限制),對其單位要求的理解來自公式結構本身與 PSR/DSR 的二手轉述。此處的推論(`SR_hat`/`γ3`/`γ4`/`n` 必須同單位)在數學上是自洽的,但**仍應在取得 Bailey & López de Prado 原文後核實**(見 [`reading-list.md`](../reading-list.md) 第 3 節)。
- **第 3 節「修正後」的兩組數字都建立在假設的 `σ_SR` 上**,真實值要等 Pass B 才知道。**因此本提案不宣稱「真正的門檻就是 2.5」或「就是 4.7」,只宣稱「原本的 1.38 是用錯誤單位算出來的,真值明顯更高」。**
