## 0. 一句話

**把「打敗市場的風險調整報酬」拆成兩層:一層是不宣稱 edge、機械上必定做得到的回撤控制(可交付);另一層是宣稱 edge 的超額 Sharpe(可選,而且比原目標更難)。**

## 1. 我上一輪的一個錯誤,必須先更正

[`target-reassessment.md`](./target-reassessment.md) 第 4 節說選項 D「不要求你找到市場沒有的 alpha」。

**這句話只有一半對,而且錯的那一半很重要。**

把 BTC 曝險縮到 `w` 倍:

| 曝險 `w` | 年化報酬 | MDD | **Sharpe** | 保留報酬比 |
|---|---|---|---|---|
| 0.20 | 7.0% | 16.6% | **0.44** | 20% |
| 0.36 | 12.6% | 30.0% | **0.44** | 36% |
| 0.50 | 17.5% | 41.6% | **0.44** | 50% |
| 1.00 | 35.0% | 83.2% | **0.44** | 100% |

**Sharpe 完全不變 —— 縮放曝險不改變風險調整後報酬。**

所以「在 MDD ≤ Y 的前提下保留 X% 的報酬」這件事,拆開來看是:

- **保留比例 = `w`(= Y / 83.2%)** → 零技巧,機械後果
- **保留比例 > `w`** → **等價於策略 Sharpe > 基準 Sharpe**,這就是 alpha 主張,沒有變得比較容易

**而配對檢定顯示它其實更難**(見第 3 節):要證明 Sharpe 高於基準 0.44,在 `ρ=0.7`、`N=5` 下需要差距 **0.78**(穩健版本重算後,見 3.4 節),即絕對 Sharpe **1.22** —— 高於「證明 Sharpe > 0」的絕對門檻 0.94。

**我上一輪把這件事說反了。** 修訂後的提案建立在正確的版本上。

## 2. 因此:目標分成兩層

### 第一層:回撤控制(**必達**,不宣稱 edge)

```
在整個驗證期間,最大回撤 ≤ Y
且 保留的買進持有報酬比例 ≥ Y / MDD_基準
```

第二個條件是「零技巧基準」—— 它只是確認**沒有比單純降曝險更差**。

**這一層不需要 DSR 檢定,因為它不宣稱任何 edge。** 需要驗證的是「這個機制可靠地把回撤壓在 Y 以下」,那是風控驗證(蒙地卡羅 + 全樣本檢查),不是顯著性檢定。

⚠️ **這一層有真實價值,但價值來源是行為面而非統計面:** BTC 給你 35% 年化,代價是 83% 回撤。多數人撐不過去 —— 真正的替代方案不是「抱著 BTC 然後沒事」,而是「抱著 BTC 然後在最低點恐慌賣出」。一個機械規則能穩定交付 30% 回撤,即使 alpha 為零也有用。**但這個主張必須誠實標示為效用主張,不得包裝成 edge。**

### 第二層:超額 Sharpe(**可選**,宣稱 edge)

```
策略 Sharpe − 買進持有 Sharpe ≥ Δ,以配對檢定驗證
```

**若做不到,正確的做法是宣告「不主張 edge」,只交付第一層 —— 而不是放寬 Δ。**

## 3. 配對檢定的設計(補上先前標記為未推導的部分)

### 3.1 統計量

Jobson–Korkie (1981) + Memmel (2003) 修正,兩個 Sharpe 之差的漸近變異數:

```
Var(SR₁ − SR₂) = (1/T)·[ 2 − 2ρ + ½(SR₁² + SR₂² − 2·SR₁·SR₂·ρ²) ]
```

**關鍵項是 `2 − 2ρ`:相關性越高,共同市場因子抵銷越多,變異數越小、檢定力越高。** 這就是「配對比較更有力」的來源,現在是可算的,不是修辭。

### 3.2 但這個優勢**只在高相關時存在**

最小可偵測的年化 Sharpe 差距(`T=3271` 日、基準 Sharpe 0.44、95% 信心、含 `N` 的多重比較懲罰):

| 相關 `ρ` | `N=1` | `N=5` | `N=10` |
|---|---|---|---|
| 0.0 | 0.78 | **1.34** | 1.52 |
| 0.3 | 0.65 | 1.12 | 1.27 |
| 0.5 | 0.55 | 0.95 | 1.08 |
| **0.7** | 0.43 | **0.74** | 0.83 |
| 0.9 | 0.25 | **0.42** | 0.48 |

> 對照:絕對門檻(對照 `SR=0`)在 `N=5` 是 0.94。
>
> ⚠️ **本表為常態假設下的數字,已被 3.4.4 節的穩健版本取代**(門檻上升約 6%)。保留於此以便對照。

**`ρ` 低於 0.5 時,配對檢定比絕對檢定更差** —— 因為你在估計兩個都有雜訊的量。

### 3.3 🔴 由此得到一個非顯然的設計約束

**要享受配對檢定的檢定力,策略必須與基準高度相關(`ρ ≥ 0.7`)—— 也就是說,它必須是「大部分時間在市、偶爾降風險」的疊加型策略,不是「大部分時間空手、偶爾進場」的擇時型策略。**

策略一的在市時間只有 16.5%,估計 `ρ ≈ 0.41`(iid 假設下 `ρ ≈ √0.165`)。**在那個相關度下,配對檢定的門檻是 1.03,比絕對檢定的 0.94 還高 —— 選項 D 對策略一毫無幫助。**

這個約束是從數學推出來的,不是偏好。**它應該寫進策略二的假說文件,作為設計限制。**

### 3.4 ✅ 穩健版本已實作並重算(2026-08-08)

`analysis/sharpe_difference.py` 已實作 Ledoit–Wolf 的 HAC 標準誤(delta method)
+ studentized 循環區塊 bootstrap,7 項測試通過。**重算結果與預期不同,值得說明。**

#### 3.4.1 肥尾幾乎不影響標準誤 —— 但原因不是報酬接近常態

BTC 日報酬實測**峰度 18.837、偏度 −0.958**,顯然遠離常態。但單一 Sharpe 的
非常態修正項為:

```
Var(SR) ≈ (1/T)·[ 1 + SR²/2 − SR·γ₃ + SR²(γ₄−3)/4 ]
```

代入日頻數值(`SR_daily = 0.44/√365 = 0.0230`):

| 項 | 值 |
|---|---|
| 1 | 1.000000 |
| `SR²/2` | 0.000265 |
| `−SR·γ₃` | 0.022063 |
| `SR²(γ₄−3)/4` | 0.002100 |
| **合計** | **1.0244** → 標準誤只增加 **1.2%** |

**關鍵:所有高階動差項都乘上 `SR` 或 `SR²`,而日頻 Sharpe 只有 0.023,所以被壓掉了。**
這不是因為報酬接近常態,而是因為**日頻的 Sharpe 太小**。

#### 3.4.2 真正的修正來自自相關

真實 BTC/ETH 資料上,HAC 標準誤比忽略自相關的估計高 **6.3%**。

**實測總膨脹因子(真實 BTC/ETH,`ρ=0.798`):HAC SE ÷ 常態理論 = 1.056。**

#### 3.4.3 真實資料驗證

用 BTC vs ETH(兩者都是真實市場序列)跑完整檢定:

| | |
|---|---|
| `SR_BTC − SR_ETH`(日) | 0.0110(年化 0.21) |
| HAC 標準誤 | 0.01174 |
| `z` | 0.937 |
| **bootstrap p** | **0.343** |

**BTC 與 ETH 的年化 Sharpe 差了 0.21(0.44 vs 0.23),9 年資料仍無法在統計上區分。**
這是一個很有用的校準:它讓「要證明 Δ ≥ 0.78」這件事的難度有了直觀的參照。

#### 3.4.4 重算後的門檻

| 相關 `ρ` | `N=1` | `N=5` | `N=10` | 原值(`N=5`)→ 新值 |
|---|---|---|---|---|
| 0.0 | 0.82 | 1.42 | 1.61 | 1.34 → **1.42** |
| 0.3 | 0.69 | 1.18 | 1.34 | 1.12 → **1.18** |
| 0.5 | 0.58 | 1.00 | 1.14 | 0.95 → **1.00** |
| **0.7** | 0.45 | **0.78** | 0.88 | 0.74 → **0.78** |
| 0.9 | 0.26 | 0.45 | 0.51 | 0.42 → **0.45** |

**門檻上升約 6%,結論的方向不變。** 3.3 節的設計約束(`ρ` 必須 ≥ 0.7)也不變。

## 4. 建議的具體數字

### 4.1 回撤上限 `Y`:**30%(已定案 2026-08-08)**

原目標的 15–20% 在年化波動 68% 的市場上,只能靠把曝險壓到 `w ≤ 0.24`,報酬僅 8.4% —— **那已經接近「不參與」**。

| `Y` | 允許曝險 `w` | 零技巧報酬 | 評語 |
|---|---|---|---|
| 20% | 0.24 | 8.4% | 過度保守,接近不參與 |
| **30%** | **0.36** | **12.6%** | **建議** |
| 40% | 0.48 | 16.8% | 多數人撐不住 |

**這是風險偏好,不是數學結論。** 專案負責人已於 2026-08-08 決定採 **30%**。

### 4.1b 比較基準:**每日再平衡等權 50/50 BTC/ETH(已定案 2026-08-08)**

實測(`analysis/benchmark.py`,`n=3270`):

| | CAGR | Sharpe | MDD |
|---|---|---|---|
| **每日再平衡等權 50/50** | **28.59%** | **0.3405** | **88.32%** |
| *(未採用)買進持有不再平衡 50/50* | 29.90% | 0.3650 | 87.02% |
| *(未採用)BTC 單一* | 35.00% | 0.4400 | 83.20% |

**為什麼是 50/50 而不是 BTC 單一:** [`scope.md`](../scope.md) 定義的標的池就是 BTC + ETH。用 BTC 單一當基準,等於把「BTC 與 ETH 之間怎麼配置」的功過也算到策略頭上,而那不是策略要回答的問題。**兩標的策略應對照兩標的基準。**

**為什麼是每日再平衡而不是不再平衡:** 不再平衡的權重會隨相對表現漂移,**結果因此依賴起始日** —— 同一個策略換個回測起點就對應到不同的基準。每日再平衡是無參數且唯一的。而且不再平衡版本(Sharpe 0.3650)對策略比較**有利**,**基準的選擇不應該偏向讓策略好看**。

> ⚠️ **誠實揭露:50/50(0.3405)確實比 BTC 單一(0.44)更容易超越。** 此選擇由專案負責人於 2026-08-08 定案,**時點早於任何策略二接觸資料**,符合預先登錄紀律。上述方法論理由是真的,但「它也比較容易」同樣是事實,兩者都記錄在案。

**基準定義已寫入 `analysis/benchmark.py` 並有測試鎖住**(8 項),不是文件裡的一個數字 —— 基準是治理參數,與門檻同級,若只存在於文件,日後重算的細微定義差異會直接改變通過與否。

### 4.2 第一層(必達):`MDD ≤ 30%` 且 保留報酬 ≥ **34.0%**

零技巧基準 = 30.00% / 88.32% = **33.97%**,對應年化報酬 **≥ 9.71%**(= 28.59% × 0.3397)。

### 4.3 第二層(可選):`Δ ≥ 0.78`(即絕對 Sharpe ≥ **1.12**)

依**選項 B**,這個門檻取自 **3.4.4 節穩健版本重算後**的可驗證下限(`ρ≥0.7`、`N=5`),**不因為難就調低**。

**策略一在此:Sharpe 0.50 → `Δ = 0.16`,遠低於 0.78。且其報酬/回撤比 0.30 低於基準的 0.32(28.59/88.32),連第一層都不通過。**

### 4.4 移除的舊目標

- ❌ **年化報酬 20–30%** —— 這個絕對數字與回撤上限矛盾(見 5.1),且報酬應是「回撤預算 × 市場提供的 Sharpe」的**結果**,不是可以獨立設定的目標
- ❌ **絕對 Sharpe 1.0–1.5** —— 由第二層的相對門檻取代

## 5. 必須記錄的事實

### 5.1 原目標的內部矛盾

無論本提案是否通過,以下事實應寫入 [`scope.md`](../scope.md),因為它**獨立於任何回測結果**:

蒙地卡羅(8.96 年 × 20,000 次)顯示,一個**完美達成**「年化 20%、Sharpe 1.0」的策略,有 **92.6%** 的機率違反 20% 的回撤上限;四個目標組合裡只有一個(20% + Sharpe 1.5)勉強守得住,而它仍有 61.7% 機率超過 15%。

**三個目標數字不能同時成立。** 這在 Phase 0 定案時就存在,只是沒有人算過。

### 5.2 目標可驗證性的設計原則

新增到 [`scope.md`](../scope.md):**任何績效目標在設定時必須先算過對應的驗證門檻,並確保目標高於門檻一個明確餘裕。** 原目標的下緣 1.0 貼在 `N=5` 門檻 0.94 上、低於 `N=10` 的 1.07 —— 那是一個「達成了也證明不了」的目標。
